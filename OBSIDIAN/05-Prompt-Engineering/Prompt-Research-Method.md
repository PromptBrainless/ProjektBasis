# Prompt Research Method

## Principle

Do not archive a prompt merely because it produces an attractive result once.

## Research sequence

1. Define the task and target system.
2. Read authoritative provider documentation.
3. Identify supported input/output controls.
4. Record provider-specific syntax separately from provider-neutral concepts.
5. Build a minimal prompt.
6. Add only controls justified by the task or documentation.
7. Test representative cases.
8. Record failures and limitations.
9. Assign a status: DRAFT, RESEARCHED, TESTED, VALIDATED or DEPRECATED.

## Rule

Never turn provider folklore, social-media prompt collections or one-off successful generations into canonical PB-GDS knowledge without evidence.
